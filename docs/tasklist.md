# musicBot MVP タスクリスト

## 目的

Jockie Music 風の最小音楽 Bot を、テキストコマンドベースで安定動作させる。
最初のゴールは、コマンドのみで Jockie の基本機能を代替できる状態を作ること。
その中心は `m!p <url|query>` を起点にした基本再生フローの完成。

## マイルストーン

### 0. フェーズ方針を固定する

- [ ] 今回は GUI と歌詞を実装対象外に固定する
- [ ] 今回は Jockie 基本機能のコマンド対応を最優先にする
- [ ] 低遅延化の計測ポイントを最初に決める

### 1. プロジェクト土台を作る

- [ ] `package.json` を作成する
- [ ] Node.js 20+ 前提の ESM 構成にする
- [ ] `discord.js` と `@discordjs/voice` を導入する
- [ ] 開発用スクリプトを定義する
- [ ] `.gitignore` を作成する
- [ ] `.env.example` を作成する
- [ ] 必須環境変数チェックを実装する
- [ ] 将来の GUI 拡張を見据えて UI 層と再生ロジックを分ける前提を決める

### 2. 基本ファイル構成を作る

- [ ] `src/index.*` を作成する
- [ ] `src/config.*` を作成する
- [ ] `src/commands/` を作成する
- [ ] `src/features/music/` を作成する
- [ ] `src/lib/` を作成する
- [ ] ロガーの薄いラッパを用意する

### 3. メッセージコマンド基盤を実装する

- [ ] プレフィックス `m!` を定義する

- [ ] コマンド名と引数をパースする
- [ ] エイリアスを解決できるようにする
- [ ] 未知のコマンドを無視する
- [ ] Bot 自身のメッセージを無視する

### 4. Guild 単位セッション管理を実装する

- [ ] guild ごとの音楽セッションを保持するストアを作る
- [ ] `connection`、`player`、`queue`、`currentTrack` を管理できるようにする
- [ ] セッションの取得・生成・破棄 API を用意する

### 5. VC 接続処理を実装する

- [ ] 実行者の VC 情報を取得する
- [ ] VC 未参加時のエラー処理を入れる
- [ ] Bot が VC に参加する処理を作る
- [ ] 既存接続の再利用を実装する
- [ ] 別 VC 使用中エラーを実装する
- [ ] 退出処理を実装する

### 6. 楽曲解決レイヤーを実装する

- [ ] URL と検索語を判定する

- [ ] 検索語から 1 曲を解決できるようにする
- [ ] `Track` 形式へ正規化する
- [ ] 将来の歌詞機能に備えて `title` と `artist` を扱える形にする
- [ ] 解決失敗時の例外処理を入れる

### 7. 再生エンジンを実装する

- [ ] `AudioPlayer` を作成する
- [ ] 1 曲を再生する処理を作る
- [ ] 曲終了時に次曲へ進む処理を作る
- [ ] キューが空のとき停止状態に戻す
- [ ] 再生中フラグや一時停止状態を管理する
- [ ] 主要イベントのログを出す
- [ ] 遅延計測のため、楽曲解決、VC 接続、再生開始までの時間を追えるようにする

### 8. MVP コマンドを実装する

- [ ] `play` / `p`

### 9. 応答メッセージを整える

- [ ] 成功メッセージの文言を揃える

- [ ] 再生開始、追加、停止、スキップの表示内容を統一する
- [ ] キュー追加時の UX を Jockie より分かりやすくする

### 10. 将来拡張の足場を作る

- [ ] 歌詞機能を追加するときのコマンド仕様メモを残す

## 保留メモ

- どの音源取得ライブラリを使うかは実装前に確定する
- YouTube 側仕様変更の影響を受けやすいので、依存選定時に保守性を見る
- 将来的にスラッシュコマンド対応する余地を残しておく
- 歌詞 API を使う場合は利用規約とレート制限も確認する
- GUI 版を Discord 内 UI にするか Web にするかで設計の最適解が少し変わる
