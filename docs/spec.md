# musicBot MVP 仕様書

## 概要

`musicBot` は Discord のテキストコマンドで操作する音楽再生 Bot です。
初期フェーズでは、一般的によく使われる Jockie Music 系の操作感を参考にしつつ、まずはコマンドのみで Jockie の基本機能を安定して使えることを目的とします。
特に `m!p <url|query>` を中心とした再生フローを最優先とします。

本仕様書は MVP の対象範囲を定義し、以後の実装・テスト・README 作成の基準とします。

## 開発背景

この Bot を作る主な理由は以下です。

- Jockie Music は再生開始や操作反映に遅延を感じる
- 歌詞表示のような欲しい機能が不足している
- キュー追加や再生操作はできるが、全体的な UX がよくない
- 将来的に GUI ベースの操作画面も作りたい

そのため、本 Bot は「Jockie 風の基本操作を保ちつつ、体験品質を改善する」ことを重視する。

## 現フェーズの優先順位

このフェーズでは一気に広げず、以下の順で価値を出す。

1. コマンドだけで Jockie の基本機能を使えるようにする
2. 再生開始、スキップ、停止などの体感遅延をできるだけ小さくする
3. その後に歌詞、GUI、追加 UX 改善へ広げる

## 目的

- Discord のテキストチャンネルから音楽再生を操作できるようにする
- ユーザーがいる VC に Bot が参加し、音楽を再生できるようにする
- 1 曲再生だけでなく、再生キューを使った連続再生を可能にする
- Jockie Music でよく使われる基本操作を違和感なく使えるようにする
- 反応速度のよい操作体験を目指す
- 将来の歌詞機能、GUI 機能を追加しやすい構成にする

## プロダクト方針

### 1. 低遅延

- コマンド実行から応答までの待ち時間をできるだけ短くする
- 特に `play`、`skip`、`pause`、`resume` は体感速度を重視する
- 実装時は音源解決、ストリーム取得、VC 接続のどこが遅いか切り分けられるようにログを設計する
- 目標は「ほぼ 0 に感じる体感速度」だが、外部サービスやネットワーク都合で完全な 0 遅延は保証できない
- そのため、MVP では「無駄な待ちを減らし、操作後すぐに反応が返ること」を実装上の目標とする

### 2. 歌詞機能を見据える

- MVP では歌詞機能を実装対象外とする
- ただし、将来的に `lyrics` コマンドを追加できるよう、楽曲メタデータの保持方針を意識する
- `title` や `artist` を後から扱いやすいデータ構造にしておく

### 3. UX 改善

- コマンド名は短く分かりやすくする
- 成功時と失敗時の応答を簡潔にする
- キュー追加、再生開始、スキップ結果が一目で分かる文面にする
- 将来的にボタンやセレクトメニューへ広げやすい責務分離にする

### 4. GUI 拡張性

- 再生ロジックと UI 層を分離する
- テキストコマンド実装に閉じない service 設計にする
- 将来は Discord 上のボタン UI、あるいは外部ダッシュボード UI へ展開可能な構成を目指す

## MVP の対象機能

- プレフィックスコマンドによる操作
- `m!p <url|query>` での再生またはキュー追加
- Bot の VC 参加・退出
- 再生キュー管理
- 現在再生中の曲確認
- キュー一覧確認
- スキップ
- 一時停止
- 再開
- 停止

## このフェーズの成功条件

- コマンドのみで Jockie の基本操作を一通り代替できる
- `m!p`、`m!skip`、`m!pause`、`m!resume` の反応が体感的に速い
- ユーザーが「何が起きたか」を毎回すぐ理解できる

## MVP の対象外

以下は初期実装では扱わない。

- スラッシュコマンド
- Spotify / Apple Music / Deezer など複数ソース対応
- プレイリストの高度な制御
- 歌詞表示
- ラジオ再生
- 音量変更
- リピート、シャッフル、キュー並び替え
- エフェクト、フィルタ
- 権限ロール、DJ モード、投票スキップ
- セッション永続化
- DB 保存
- GUI 画面の提供
- 歌詞コマンド本体

## 想定技術方針

- Node.js 20+
- `discord.js` v14
- ESM
- 音声接続は `@discordjs/voice`
- 音源取得は実装時に候補比較するが、MVP では YouTube URL と検索語の再生を最優先とする

## 想定コマンド一覧

### `m!p <url|query>`

- 役割:
  曲の検索または URL 指定による再生開始・キュー追加
- 入力:
  - YouTube URL
  - 検索語
- 動作:
  - 実行者が VC にいない場合はエラーを返す
  - Bot が未接続なら実行者の VC に参加する
  - 再生中の曲がなければ即時再生する
  - 再生中ならキュー末尾へ追加する
- 応答:
  - 再生開始時: 曲名、長さ、リクエスト者
  - キュー追加時: 曲名、キュー位置

### `m!join`

- 役割:
  Bot を実行者の VC に参加させる
- 動作:
  - 実行者が VC にいる場合のみ参加
  - すでに同じ VC にいる場合はその旨を返す

### `m!leave`

- 役割:
  Bot を VC から退出させる
- 動作:
  - 再生停止
  - キュー破棄
  - VC 切断

### `m!stop`

- 役割:
  再生を停止し、キューをクリアする
- 動作:
  - 現在再生中の曲を停止
  - 待機キューを空にする
  - MVP では `leave` と同等に VC 退出まで行う方針とする

### `m!skip`

- 役割:
  現在の曲をスキップする
- 動作:
  - 次の曲があれば自動再生
  - 次の曲がなければ停止状態へ遷移

### `m!pause`

- 役割:
  現在の曲を一時停止する

### `m!resume`

- 役割:
  一時停止中の曲を再開する

### `m!queue`

- 役割:
  キュー一覧を表示する
- 表示内容:
  - 現在再生中の曲
  - 次の 5〜10 曲程度
  - 件数

### `m!nowplaying`

- 役割:
  現在再生中の曲情報を表示する
- 表示内容:
  - 曲名
  - URL
  - 長さ
  - リクエスト者
  - 再生状態

## コマンド別エイリアス方針

Jockie ライクな操作感を優先し、MVP では以下の短縮形を持たせる。

- `m!p` -> `play`
- `m!q` -> `queue`
- `m!np` -> `nowplaying`
- `m!s` -> `skip`

実装上は「コマンド名」と「エイリアス」を分離して持つ。

## ユーザーフロー

1. ユーザーが VC に参加する
2. テキストチャンネルで `m!p <url|query>` を送る
3. Bot が VC に参加する
4. 楽曲情報を解決する
5. 再生キューに積む
6. 再生中でなければ先頭曲を再生する
7. 曲終了時に次曲があれば自動再生する
8. キューが空になったら待機状態になる

## 状態管理

サーバーごとに独立した再生状態を持つ。

### GuildSession

- `guildId`
- `textChannelId`
- `voiceChannelId`
- `connection`
- `player`
- `queue`
- `currentTrack`
- `isPaused`

### Track

- `title`
- `artist`
- `url`
- `duration`
- `requestedBy`
- `sourceType`

## キュー仕様

- キューは guild 単位で保持する
- FIFO を基本とする
- `play` 実行時は末尾追加
- `skip` 時は先頭を取り出して次曲へ進む
- `stop` / `leave` で全消去

## VC 参加ルール

- 原則として実行者がいる VC のみを対象とする
- Bot が別 VC にいる場合:
  - MVP では「すでに別 VC で使用中」としてエラーを返す
  - 自動移動は行わない

## 応答メッセージ方針

- エラーは短く、人間に分かりやすく返す
- 成功時は曲名と次の状態が分かるように返す
- 内部エラーは詳細をログに出し、ユーザーには簡潔な失敗メッセージを返す

例:

- VC 未参加: `先にボイスチャンネルに参加してください。`
- 曲未検出: `曲を見つけられませんでした。URL または検索語を確認してください。`
- 再生失敗: `再生に失敗しました。少し時間を置いてもう一度試してください。`

## ログ方針

最低限以下を出力する。

- Bot 起動完了
- コマンド受信
- VC 参加 / 退出
- 楽曲解決成功 / 失敗
- 再生開始
- 再生終了
- 主要エラー

ログに含めたい識別子:

- guildId
- userId
- channelId
- commandName
- trackUrl

## テスト観点

### 遅延観点

- `m!p` 実行後、受理メッセージがすぐ返る
- `m!skip` 実行後、次曲への遷移が不自然に遅くない
- `m!pause` / `m!resume` が即時に近い体感で反応する
- ログで「楽曲解決」「VC 接続」「再生開始」までの時間を追える

### 正常系

- `m!p <YouTube URL>` で再生開始できる
- `m!p <query>` で検索再生できる
- 再生中に `m!p` するとキュー追加される
- `m!skip` で次曲へ進む
- `m!pause` / `m!resume` が動く
- `m!queue` で一覧表示できる
- `m!leave` で退出できる

### 異常系

- VC 未参加で `m!p` すると弾かれる
- 曲取得失敗時に落ちない
- 空キューで `m!skip` しても落ちない
- 未接続時の `m!leave` / `m!stop` で落ちない
- 別 VC 使用中に割り込めない
